## Findings and fixes
- Release identity previously hashed only JS/WASM/PCK. HTML, manifest and
  icon-only updates could reuse an old service-worker cache. Hash all fresh
  index assets, HTML and manifest, with an explicit worker-policy version.
- CacheStorage is shared across an origin. Activation previously deleted all
  Lantern March caches, including other deployment paths. Cache names now own
  an encoded registration scope; activation deletes only older caches in that scope.
- Network-first navigation could show a new shell before its worker completed
  installation. Serve the active worker's cached shell; retain normal waiting-worker
  activation (no skipWaiting or clients.claim).
- Validate fresh required files and parse the manifest before renaming output.

Legacy unscoped caches are intentionally retained: their owning deployment cannot
be inferred safely. Do not clear origin-wide storage as part of migration; it could
remove saves. The first v2 installation does not retroactively alter old workers.
